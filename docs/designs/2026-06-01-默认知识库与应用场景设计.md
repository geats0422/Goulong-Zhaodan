# 默认知识库与应用场景设计

## 目标
将 `reference/招投标法律法规（新）-用于照胆` 中的现行法规导入为系统默认知识库，并让审查流程同时使用默认知识库、用户自定义知识库和用户配置的违禁词。知识库文档新增“应用场景”维度，用于区分招投标和合同审查。

## 用户场景
用户在知识库页面上传文档时，选择应用场景：`招投标` 或 `合同`。上传后的文档进入个人知识库，可在设置页启停。

系统启动或执行导入脚本时，将 reference 目录内默认法规导入系统级知识库。文件名包含招投标、招标、投标、评标、政府采购、质疑、投诉、公示等关键词的文档归为招投标场景；文件名包含合同、民法典合同编、合同通则等关键词的文档归为合同场景。

用户上传待审查文件时，审查 Agent 同时读取：
- 默认知识库中与当前应用场景匹配的法规依据
- 当前用户启用的个人知识库中与当前应用场景匹配的文档
- 当前用户在设置页配置的违禁词

## 技术方案
采用最小侵入式扩展现有知识库模型。

新增文档属性：
- `owner_type`: `system` 或 `user`，区分默认知识库与用户知识库
- `owner_user_id`: 用户知识库归属用户，系统默认知识库为空
- `application_scenario`: `bidding` 或 `contract`
- `source_path`: 默认知识库导入时记录原始 reference 文件路径，用于幂等导入

前端知识库上传弹窗新增应用场景单选，并修复主题样式，使浅色/深色下弹窗、输入框、选择框、按钮一致。

后端知识库上传 API 新增 `application_scenario` 表单字段。用户上传的文档写入 `owner_type=user`、`owner_user_id=current_user_id`。

默认知识库通过独立导入脚本实现，不放入请求链路中执行。脚本扫描 reference 目录，按文件名推断应用场景，复用现有 `convert_to_markdown` 和 `build_index_nodes` 入库能力。导入脚本必须幂等，重复执行不会创建重复文档。

## 数据模型
### `knowledge_documents` 新增字段
- `owner_type: String(20), default='user'`
- `owner_user_id: Integer | None, ForeignKey('users.id'), nullable=True`
- `application_scenario: String(20), default='bidding'`
- `source_path: String(1000) | None, unique nullable`

### 应用场景枚举
- `bidding`: 招投标
- `contract`: 合同

### 兼容策略
现有用户上传文档迁移后默认：
- `owner_type='user'`
- `owner_user_id=NULL`
- `application_scenario='bidding'`

如果后续需要严格用户隔离，可补充数据修复脚本回填历史文档归属。

## 接口设计
### 知识库上传
`POST /api/v1/knowledge/upload`

新增表单字段：
- `application_scenario`: `bidding | contract`

响应新增字段：
- `application_scenario`

### 知识库概览
`GET /api/v1/knowledge/overview`

返回结构中每个文档增加：
- `owner_type`
- `application_scenario`

展示策略：
- 默认知识库和用户知识库都可展示
- 默认知识库可加“系统默认”标识
- 用户知识库保留重命名/删除入口

### 体检上传
`POST /inspection/upload`

新增表单字段：
- `application_scenario`: `bidding | contract`，默认 `bidding`

审查依赖新增：
- `regulation_base`: 根据应用场景聚合后的默认知识库与用户知识库内容
- `taboo_words`: 当前用户保存的违禁词 + 临时传入违禁词

## 默认知识库导入
新增脚本建议路径：

`backend/scripts/import_default_knowledge.py`

输入目录：

`reference/招投标法律法规（新）-用于照胆`

分类规则：
- 文件名包含 `合同`、`民法典` 且语义指向合同编/合同通则：`contract`
- 文件名包含 `招标`、`投标`、`招投标`、`评标`、`政府采购`、`质疑`、`投诉`、`公示`：`bidding`
- 无法判断：默认 `bidding`，并输出导入日志提示

幂等规则：
- 使用 `source_path` 识别是否已导入
- 已导入文档跳过
- 文件变更检测暂不做版本自动更新，后续可引入内容 hash

## 审查召回策略
新增服务函数建议路径：

`backend/services/knowledge_retrieval.py`

输入：
- `db`
- `user_id`
- `application_scenario`
- `limit`

输出：
- 默认知识库片段
- 用户启用知识库片段
- 来源文档标题与路径标签

初版召回策略：
- 查询 `KnowledgeDocument.application_scenario == application_scenario`
- 系统默认：`owner_type='system'`
- 用户知识库：`owner_type='user'` 且用户未在设置中禁用
- 按 `IndexNode.position` 和文档创建时间取前若干片段

后续可升级为关键词/BM25/向量检索，但本次先确保默认知识库与用户知识库能共同进入审查上下文。

## 错误处理
- 上传弹窗主题：不再使用固定黑白背景，统一使用主题变量，避免浅色模式下输入框不可读。
- 应用场景非法：返回 400。
- 默认知识库目录不存在：导入脚本报错并退出，不影响服务启动。
- 单个默认法规转换失败：记录失败原因，继续导入其他文件。
- 用户知识库为空：审查仍使用默认知识库和违禁词。
- 默认知识库为空：审查仍使用用户知识库和违禁词，但报告提示法规依据不足。

## 测试策略
### 后端
- 知识库上传必须接受并保存 `application_scenario`
- 非法应用场景返回 400
- 默认知识库导入脚本按文件名归类合同/招投标
- 导入脚本重复执行不重复创建文档
- 体检上传构建依赖时包含用户保存违禁词
- 体检上传构建依赖时包含默认知识库和用户启用知识库

### 前端
- 上传弹窗包含应用场景单选：招投标/合同
- 上传请求包含 `application_scenario`
- 浅色主题下弹窗输入框、select、按钮可读
- 知识库页面不再出现 HTML 当 JSON 解析的问题

### 验证命令
- 后端：`python -m pytest tests/ -v --tb=short`
- 前端：`npm run test:routes`
- 前端构建：`npm run build`

## 非目标
本次不实现全文搜索排序、向量数据库、内容 hash 增量更新、复杂多租户权限、知识库删除系统默认文档。
