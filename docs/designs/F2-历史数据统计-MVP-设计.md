# F2 历史数据统计 MVP 设计

## 1. 目标与范围

基于功能列表中的 F2 历史数据统计，第一期（MVP）上线基础三件套统计能力，为用户提供最近 7 天的核心运营视图。

MVP 范围：

- 上传文档数
- 违禁词出现率（按文档命中率）
- 额度消耗

不在 MVP 范围：

- 按小时粒度
- 高频违禁词 TopN
- 文件类型分布
- 团队/平台级多租户统计聚合

## 2. 已确认产品决策

- 指标组合：基础三件套（上传文档数 + 违禁词出现率 + 额度消耗）
- 默认时间范围：近 7 天
- 趋势粒度：按天
- 违禁词出现率口径：`命中违禁词的文档数 / 总文档数`
- 统计隔离范围：按当前登录用户（只看自己的统计）

## 3. 指标定义

### 3.1 上传文档数

- 定义：用户在统计区间内上传并进入处理流程的文档数量
- 统计单位：份

### 3.2 违禁词出现率

- 定义：统计区间内，命中至少 1 个违禁词的文档占比
- 公式：`hit_docs / total_docs`
- 展示：百分比（如 23.5%）
- 边界：当 `total_docs = 0` 时返回 `0`，前端显示 `0%`

### 3.3 额度消耗

- 定义：统计区间内用户累计消耗额度
- 统计单位：点/次（按现有额度系统单位）
- 展示：整数或保留两位小数（与现有额度展示规则保持一致）

## 4. 时间与分桶规则

- 默认区间：`[今天-6天, 今天]`，共 7 个自然日
- 分桶粒度：按天
- 时区：统一使用系统业务时区（建议与后端当前配置保持一致）
- 产出数据：
  - 汇总卡片（区间总量/均值/占比）
  - 7 天趋势序列（每个指标一组按天数据）

## 5. 后端设计（FastAPI）

## 5.1 API 草案

- 路由：`GET /api/v1/stats/history`
- 鉴权：必须登录，基于当前用户 ID 过滤
- 参数：
  - `range`: 可选，默认 `7d`（MVP 可仅支持 `7d`）
  - `start_date`, `end_date`: 可选（MVP 可先不开放，后续扩展）

响应示例：

```json
{
  "range": "7d",
  "timezone": "Asia/Shanghai",
  "summary": {
    "total_docs": 120,
    "hit_docs": 34,
    "banned_rate": 0.2833,
    "quota_consumed": 560
  },
  "trend": {
    "dates": ["2026-05-24", "2026-05-25", "2026-05-26", "2026-05-27", "2026-05-28", "2026-05-29", "2026-05-30"],
    "total_docs": [12, 18, 15, 20, 19, 16, 20],
    "hit_docs": [4, 5, 3, 7, 6, 4, 5],
    "banned_rate": [0.3333, 0.2778, 0.2, 0.35, 0.3158, 0.25, 0.25],
    "quota_consumed": [56, 82, 70, 95, 88, 77, 92]
  }
}
```

## 5.2 数据来源

- 上传文档数：来源于文档上传/处理主表（按用户 + 日期聚合）
- 命中文档数：来源于审核结果表或违禁词检测结果（按文档是否命中去重）
- 额度消耗：来源于额度流水表（按用户 + 日期求和）

## 5.3 查询策略

- 单次请求内返回汇总与趋势，避免前端多次拉取
- 先聚合再计算比率，避免行级实时计算导致的开销
- 缺失日期补零，保证趋势数组固定 7 个点

## 6. 前端设计（Vue 3）

## 6.1 页面结构

- 顶部：时间范围选择（MVP 默认并固定近 7 天，可预留下拉）
- 中部：3 张指标卡片
  - 上传文档数（总量）
  - 违禁词出现率（百分比）
  - 额度消耗（总量）
- 底部：趋势图区域
  - 折线 1：上传文档数
  - 折线 2：违禁词出现率
  - 折线 3：额度消耗

## 6.2 状态与交互

- 首次进入自动拉取 `7d`
- 加载态：卡片 skeleton + 图表 loading
- 空态：无数据时显示空态文案，卡片显示 0
- 错误态：接口失败时显示可重试提示

## 7. 验收标准（MVP）

- 登录用户可看到仅属于自己的三项统计
- 默认展示近 7 天数据，按天完整连续
- 违禁词出现率计算口径与定义一致
- 汇总值与趋势值可对账（趋势求和/聚合后与汇总一致）
- 无数据、异常数据、接口失败均有可用展示

## 8. 风险与后续演进

主要风险：

- 历史数据字段不齐全（例如旧数据缺少命中标记）
- 额度流水与文档处理时间不一致导致对账差异
- 时区处理不一致导致日期边界偏移

后续迭代方向：

- 支持 30 天、本月、自定义区间
- 增加按小时查看
- 增加高频违禁词 TopN
- 增加文件类型分布
- 支持组织维度统计（权限模型完善后）

## 9. 实施建议

建议按以下顺序落地：

1. 后端先提供单一聚合接口（含汇总 + 趋势）
2. 前端完成卡片 + 趋势图 + 空/错/载状态
3. 以真实历史数据做口径对账
4. 补齐单元测试与集成测试
